Week topic is issues with pull request and merging.
The main problem is when some of us (me includes) takes more time to develop his own feature branch.
When trying to make pull request we find the develop branch is much ahead of the current branch. Some functionality can changed completely so it's need to manually resolve conflicts.
**Main rule is to develop little parts and make often pull request**

But we also have a problem with approving pull requests:
- We are a small team, so to promote collective team collaboration every team member must have approvation from other 2 team members. That will favour to review and study code of team mates.
- Unfortunetely not always all members are available to check and review pending pull requests.
So sometimes the work is blocked because there are not approved pending pull requests.
- As for me, sometimes I continued to work in current branch (so the feature became bigger) or create new branch but some code I put there manually from another not approved branch.

**I am not sure if it was good idea to stick with collective approving, because in general I see that team members tend to stick with their own components**

May be it's better way if a mentor review the code.

As for me the necessity to review code of other students is a good experience for me. As a team lead I feel myself responsible for our common project and I must be sure that all components works and are compatible with each other. All students have their own code style etc... - so I must promote uniformity of the code.
