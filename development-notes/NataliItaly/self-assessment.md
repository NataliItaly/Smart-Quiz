## Components +40

1. Rich UI Screen — Dashboard + Filters (+20)

Реализован экран, объединяющий пользовательский сценарий и управление состоянием.

Dashboard
- точка входа после авторизации
- обработка пользовательских действий (навигация, logout)
- интеграция с системой маршрутизации

Компонент сохраняет чёткое разделение ответственности: UI не смешивается с бизнес-логикой.

Filters Form (ключевая часть)

Форма фильтрации реализует более сложную логику и является основным источником состояния для викторины.

Функциональность:
- динамическая генерация UI на основе конфигурации (filterOptions)
- преобразование пользовательского ввода в доменную модель
- управление состоянием викторины

Поток данных:
user input → transform → state update

Ключевые решения:
- переиспользуемая утилита createElement
- явное преобразование данных (toCategory, toLevel, toMode)
- контролируемое обновление состояния (clearQuiz, updateQuiz)

Почему это Rich UI Screen:
- есть внутреннее состояние
- есть логика обработки пользовательского ввода
- есть связь UI с данными приложения

2. Rich UI Screen — Quiz Screen + Loader (Async Flow) (+20)

Реализована логика экрана викторины с управлением асинхронной загрузкой и пользовательским состоянием.

Важно: базовый UI викторины был предоставлен, но вся логика управления данными и поведением экрана реализована мной.

Функциональность:
- интеграция с навигацией:
- пользователь может покидать экран и возвращаться
- сохраняется текущий прогресс (последний вопрос)
  
управление состоянием:
- если данные уже загружены → повторный fetch не выполняется
- если данных нет → инициируется загрузка
- контроль жизненного цикла данных
  
Loader (часть компонента)
- отображается только при отсутствии данных
- встроен в условный рендеринг
- обеспечивает мгновенную обратную связь пользователю
  
Почему это Rich UI Screen:
- асинхронная загрузка данных
- условный рендеринг
- работа с состоянием
оптимизация запросов и UX


## Backend & Data — Firebase Integration (+15)

В проекте реализована интеграция с Firebase для работы с пользовательскими данными и состоянием приложения.

Функциональность:
- хранение пользовательских данных
- использование данных для отображения:
  - онлайн-статуса пользователей
  - лидерборда (по количеству очков)
- сохранение состояния игр:
  - пользователь может вернуться к незавершённой игре
  - прогресс не теряется между сессиями

Роль в приложении:
- данные из Firebase напрямую влияют на UI и поведение приложения
- реализована связь между:
  - авторизацией пользователя
  - состоянием игры
  - отображаемыми данными

## DevOps & Role +5
1. Auto-deploy +5
- Автоматический деплой (Netlify)
Проект автоматически разворачивается на Netlify при каждом пуше в репозиторий. Это позволяет команде и заинтересованным сторонам видеть актуальные изменения без ручных действий.
- Настройка CI/CD
- процесс непрерывной интеграции, включающий линтинг через ESLint, pre-commit хуки через Husky и автоматическое тестирование через Vitest. Это гарантирует качество кода и предотвращает попадание ошибок в основную ветку.
- Конфигурация проекта и инструменты
Проект использует TypeScript, Vite и современные сборщики. ESLint и Husky обеспечивают единый стиль кода и стандарты командной работы.
- Инфраструктура тестирования
Vitest позволяет легко писать и запускать юнит-тесты, что делает код более поддерживаемым и проверяемым.
